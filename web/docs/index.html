Strata: an excavation as one graph

Strata holds an archaeological excavation as a single Relate graph file. Every find is connected to the layer it came from, the layers above and below it, its period and its site. Checks that run as Cypher inside the file show where the excavators' own records disagree.

The store in the repository, data/strata.rl, holds the complete published record of Kenan Tepe, a mound on the Upper Tigris in south-eastern Turkey, excavated from 1998 to 2007 and published openly on Open Context:

  • 3,280 stratigraphic units
  • 14,576 recorded relations between them
  • 19,742 finds, with animal bones linked to GBIF taxa
  • 268 open issues where the records disagree

Any other excavation's Harris matrix, kept in ArchEd, Stratify, pyArchInit, Field Desktop, Harris Matrix Composer, a drawing or a spreadsheet, converts into the same kind of graph and gets the same checks (Your own matrices).

Getting started

In the browser

Open the viewer. The matrix is usable after about five seconds; the finds load behind it. Two good places to start:

  • Area F / Trench 1 / Locus 1032: dated Late Chalcolithic but lying above an Early Bronze Age I unit. The excavator's note says the bricks "may have been ancient trash", that is, redeposited older material.
  • Area A / Trench 9 / Locus 2: recorded both above and below Locus 4. The note explains why: "we separated L2 and L4 earlier in the season but found that they were equal".

In Claude Desktop

Download strata.mcpb from the latest release and open it. Then ask, for example, "What does Locus 20 in Area D, Trench 6 seal?" See Claude Desktop.

From a clone

You need Python 3.11+ and uv.

git clone https://github.com/openhistorymap/strata
cd strata
uv sync
uv run strata ask overview
uv run strata ask describe "Area F/Trench 1/Locus 1032"
uv run strata query "MATCH (i:Issue) RETURN i.kind, count(*) ORDER BY count(*) DESC"

Your own matrices

Strata reads a Harris matrix from the program it was kept in, turns every recorded relation into the graph above, and runs every check on it: matrix rows, loops, records that contradict each other, redundant relations. Nothing in the file is changed; what the file said stays on each edge (verbs, stated_by, sources).

uv run strata convert scavo.sqlite                  # → scavo.strata.json, checked; open it in the viewer
uv run strata convert matrix.lst -o my-dig.strata.json --store my-dig.rl   # also keep a Relate file
uv run strata --db mine.rl import-matrix matrix.lst --site my-dig          # add it to a store as a site
uv run strata formats                               # what can be read

The format is recognised from the file's content, so a CSV from pyArchInit, Field Desktop or a spreadsheet each go to the right reader; --format overrides it. In Claude Desktop or Claude Code, ask "Import the matrix in ~/Desktop/scavo.sqlite": the import_matrix tool does the same and reports what it read and found.

Relation words

Each program words relations its own way ("Copre", "Coperto da", "Tagliato da", "Si appoggia a", "Covered by", "Wird geschnitten", "recouvert par", isCutBy…). Strata maps them, in English, Italian, German, French and Spanish, onto its verbs: above, below, cuts, cut by, fills, filled by, seals, sealed by, same as, contemporary, abuts, within. A word it does not know is not guessed: the relation is left out and counted under skipped_relation_words in the result, so you can see what was not imported. pyArchInit's Extended Matrix connectors (>, <, >>, <<) are reported this way.

What you get

A site whose units carry the file's names, with their group (area, trench, cluster, Stratify group) as the trench the viewer draws them in, phases and periods where the file has them, and the result of every check. convert prints what it read, what it loaded and what the checks found, and writes a .strata.json bundle that the viewer opens from your disk (nothing is uploaded) or from a URL.

Tested on

  • The BASP and Stratify samples shipped with stratigraphr (bonn.lst, stratify.lst): 17 units each, 4 matrix rows, no contradictions.
  • pyArchInit's sample database: 51 units, 162 relations, 20 rows, no contradictions, 25 relations already implied by others; 25 Extended Matrix connectors reported as skipped.
  • Ulm-Eggingen (Harris Matrix Composer project and CSV export, 110 units) and Harris's figure 12 (hm data package), from harris-mcp's tests.
  • One invented dig recorded in every format above (tests/fixtures/matrices/): each reader must give the same graph.

The graph model

Every node and relationship type, as stored in data/strata.rl and in the browser:

(:Site)<-[:IN_SITE]-(:Trench)<-[:IN_TRENCH]-(:Context)           a Context is a stratigraphic unit (locus, layer, cut, fill, wall)
(:Context)-[:IN_SITE]->(:Site)                                    a unit recorded without a trench
(:Context)-[:ABOVE {verbs, stated_by, sources, redundant}]->(:Context)   later -> earlier
(:Context)-[:CONTESTED]->(:Context)                              an ABOVE claim set aside: it contradicts another
(:Context)-[:REJECTED {rejected_by}]->(:Context)                 a claim an archaeologist ruled out (kept, not deleted)
(:Context)-[:SAME_AS|ABUTS|WITHIN]->(:Context)
(:Find)-[:FROM {bag}]->(:Context)      (:Find)-[:IDENTIFIED_AS]->(:Taxon {uri})
(:Context)-[:DATED_TO {basis}]->(:Period)-[:OF_SITE]->(:Site)
(:Context)-[:IN_PHASE]->(:Phase)-[:OF_SITE]->(:Site)
(:Issue {kind, severity, detail, records, status})-[:INVOLVES {position}]->(:Context)
(:Edit {op, args, note, author, ts, status})-[:TOUCHED]->(:Context)

Every key has a uniqueness constraint. Context is also indexed on site, label and depth, Find on label, and Issue on kind. The schema is strata/schema.cypher.

Conventions

  • Direction. (a)-[:ABOVE]->(b) means a is later than b: it lies over it, cuts it, fills it or seals it. r.verbs says which; r.stated_by lists the unit records that state it, and r.sources their Open Context URIs.
  • Reciprocal records merged. "A above B" in A's record and "B below A" in B's record become one edge with both records in stated_by.
  • Years are astronomical. -3099 is 3100 BCE; year 0 is 1 BCE.
  • Dates are tentative. Kenan Tepe's periods come from field phasing. Units labelled "A / B" are linked to both periods with basis: 'either'.
  • Contradictions are kept. Nothing a record says is deleted. Claims that contradict others are retyped :CONTESTED so the rest is a clean matrix, and claims ruled out by a person become :REJECTED.

How Strata uses Relate

Mode: single file. An excavation archive is a document: it is deposited, cited, copied to a field laptop and handed to the next specialist. One .rl file is all of that. Relate opens it in-process, with no server.

WhereRelate buildStore
CLI, Python, MCP server, Claude DesktopPython wheel relate-db 1.2 (import relate)data/strata.rl or your copy, read-write
Official relate CLINative binary 1.2The same file: relate --database data/strata.rl "MATCH …"
Browser viewer@relate/relate-wasm 1.2.0 in a Web WorkerIn memory, loaded from a JSON export (the WASM build cannot open .rl)
  • Transactions. Every proposed edit is one transaction. The new relationship and a loop check run together; it commits with its :Edit log entry, or rolls back and leaves no trace.
  • Read-only access. The query tool and strata query refuse write clauses and run in a transaction that is always rolled back. The CLI opens the store read-only, so reading never changes the file.
  • One writer. Relate connections belong to the thread that opened them. The MCP server opens the store on one worker thread and hands every tool call to it, so two agents calling at once are serialised.
  • All reasoning is Cypher. Matrix rows, contradictions, redundancy, date brackets and provenance are queries; see checks.py and queries.py. A full rebuild, import plus every check, takes about 20 seconds; questions answer in milliseconds.

Stratigraphic reasoning

An excavation records stratigraphy one unit at a time: "this is above 17, 49 and 53; it is cut by 29". Together those statements form a directed graph that should be acyclic: the Harris matrix. strata check (also run by build and the recheck tool) does this, in order:

  1. Two-way contradictions. Pairs ordered both ways are found by pattern matching. Both claims are retyped :CONTESTED and the pair becomes an issue (self-contradiction, enclosed, cut-or-cover or conflicting records).
  2. Matrix rows and longer loops. Context.depth is computed by peeling the :ABOVE graph one layer per statement (Kahn's algorithm). Units left unplaced sit on a loop: shortestPath finds it, its closing edge is contested, and peeling resumes (up to 25 rounds).
  3. Other checks. Same-as conflicts, elevation conflicts (5 cm tolerance; cuts excluded) and period inversions.
  4. Redundant edges. An :ABOVE edge implied by a longer path is flagged redundant: true. The rest, the transitive reduction, is what a Harris matrix draws.
  5. Issues. Results are written as :Issue nodes linked to their units, replacing the previous run's.

Date brackets

A unit cannot be earlier than anything it seals, nor later than anything sealing it:

  • Not earlier than (terminus post quem): the latest start year among dated units below it.
  • Not later than (terminus ante quem): the earliest end year among dated units above it.

The viewer compares the recorded date with the bracket. It says whether the date fits, contradicts the stratigraphy, or fits only at the very edge of its range, as Locus 1032 does.

The browser viewer

The viewer runs the whole graph (23,432 nodes, 40,796 relationships) in Relate's WebAssembly build, in a Web Worker in your tab. There is no server behind it.

What it shows

  • Trenches (left): each with its units and open issues. Units recorded without a trench form one matrix, "Units without a trench".
  • Harris matrix (centre): rows are Context.depth. Boxes are coloured by period and outlined red when the unit has open issues. Contested claims are red dashes and same-as links are dotted. Implied relations shows redundant edges. Drag to pan, scroll to zoom, Fit to see it all.
  • Unit (right): the excavator's note, open issues, date bracket and verdict, relations, contested claims with the records that make them, finds by category with taxa, and a link to the Open Context record. Everything it seals is outlined brown, everything sealing it blue.
  • Issues tab: all issues by kind. Click one to open its trench with every unit involved highlighted.
  • Cypher console (Ctrl+`): any Cypher, run with Ctrl+Enter, plus seven example queries. Every panel has a Cypher link that opens the query behind it.
  • Theme: Auto (follows your system), Light or Dark, remembered.

Other datasets

The chip next to the title always says what is loaded and where it came from. Click it to open a dataset on the site, one at a URL, or a .strata.json file from your computer. You can also drop the file on the page. A local file is read in the tab and never uploaded; while it is loaded, the chip says Local file with its name, size and date. To make one, see Bundles.

Speed

Relate's WASM build loads about 3,000 nodes or relationships a second. The core graph (sites, trenches, units, periods, issues, the matrix) takes about five seconds and is usable at once; finds, taxa and abutments follow in about ten more. Queries take milliseconds.

Ask a model (OpenRouter)

Ask a model in the viewer's header opens a panel where you ask about the excavation in your own words. A model you choose on OpenRouter answers by calling the page's own tools (the WebMCP tools below, against the graph in your tab), and each call is shown as it happens: open one to see its arguments and result, and open a Cypher call in the console. Units in an answer are links to the matrix.

Signing in

  • Sign in with OpenRouter uses OpenRouter's OAuth PKCE flow: you authorise the page on openrouter.ai and come back with a key of your own, billed to your OpenRouter credits. A $5 limit is suggested on the consent page; you can change it there.
  • You can paste an existing key instead (Use an API key instead).
  • The key is kept in your browser's local storage and sent only to OpenRouter. Strata has no server. Sign out makes the browser forget the key and links to the key on OpenRouter, where you can delete it.

Models

The picker lists every OpenRouter model that supports tool use, with its price per million tokens; a few are suggested at the top. Claude Sonnet 5.5 is the default. The panel shows what the conversation has cost so far.

What leaves your browser

Your question, the page's description of the graph, and every tool result the model asks for go to OpenRouter and the model's provider. With harris-mcp on, the matrix described above also goes to harris.openhistorymap.org. This includes parts of a local file you opened, which otherwise never leaves the tab; the panel says so when a local file is loaded.

MCP server and tools

strata mcp serves the store over MCP (stdio) with 21 tools. These are what the Claude Desktop extension and Claude Code use. The server's instructions tell agents to answer from the graph, cite unit paths and the records behind each claim, never invent a relation, and ask before settling a dispute.

Edits, history and revert

Every change an agent or a person makes goes through a tool, never through raw Cypher:

  1. A transaction opens and the change is written, marked pending.
  2. The loop check runs: is there already a path from lower back to upper? If so, the transaction rolls back and the answer is {accepted: false, refused, chain, records}. The records are the ones that forbid the edit, with paths and Open Context URIs.
  3. Otherwise an :Edit node is written (op, arguments, note, author, timestamp) and linked to every unit it touched, the transaction commits, and the checks rerun.

history lists edits; revert undoes one and logs the reversal. Edits live in the store file, so they travel with it. A rebuild from source (strata build) starts from the published record again; keep your working store separate (see Claude Desktop, or set STRATA_DB).

Claude Desktop

Install

  1. Download strata.mcpb from the latest release.
  2. Open it, or drag it onto Claude Desktop's Settings → Extensions.
  3. Claude Desktop installs Python and the dependencies (relate-db, fastmcp, and networkx, openpyxl for the matrix readers) itself.

Where your data is

The extension carries the Kenan Tepe store as a read-only seed and never writes to it. The server picks its store in this order:

  1. The extension's Strata store setting, a .rl file you choose (or STRATA_DB in the environment).
  2. Documents/Strata/strata.rl. On first run it is created from the seed; after that it is reused, so your edits survive extension updates and the file is yours to see, copy and back up.

Ask for store_info at any time: it reports the path, why it was chosen, its size, last change and number of edits.

Your own matrix

Ask Claude to import a matrix file by its path, e.g. "Import ~/Desktop/scavo.sqlite as site scavo". It is added to the same store, checked, and from then on every tool works on it. All the formats are available in the extension; nothing else needs installing.

Without the extension

From a clone, add this to claude_desktop_config.json. STRATA_DB is optional.

{
  "mcpServers": {
    "strata": {
      "command": "uv",
      "args": ["run", "--directory", "/path/to/strata", "strata", "mcp"],
      "env": { "STRATA_DB": "/path/to/my/strata.rl" }
    }
  }
}

Build the extension

uv run python desktop/build.py                                   # -> dist/strata-desktop/
npx -y @anthropic-ai/mcpb pack dist/strata-desktop dist/strata.mcpb

desktop/build.py copies the server modules and the store, writes a pyproject.toml with only the server's dependencies, and fills the manifest (MCPB 0.4, uv server type) with the version from pyproject.toml and the tool list from the server. Pushing a v* tag builds and attaches it to the release.

Claude Code and other hosts

File formats

Relate store (.rl)

Relate's single-file format. Inspect it with relate info --database data/strata.rl, query it with the relate CLI or strata query.

Viewer export (strata-web, version 1)

The browser can't open .rl, so the graph travels as JSON. A part is:

{
  "meta":  {"part": "core", "dataset": "kenan-tepe", "built": "2026-11-22T12:49:59Z", "schema": ["CREATE CONSTRAINT …", …]},
  "nodes": [{"label": "Context", "key": "uid", "rows": [{"p": {…properties}, "pt": {"location": {"latitude": …, "longitude": …}}}]}],
  "edges": [{"type": "ABOVE", "from": ["Context", "uid"], "to": ["Context", "uid"], "rows": [[fromKey, toKey, {…properties}]]}]
}

A site is two parts: core (site, trenches, units, periods, phases, issues and their relationships) and finds (finds, taxa, FROM, IDENTIFIED_AS, ABUTS). On the site they are separate files listed in datasets.json:

{"format": "strata-web", "version": 1, "datasets": [
  {"id": "kenan-tepe", "name": "Kenan Tepe", "source": "…", "license": "CC BY 4.0", "built": "…", "store": "strata.rl",
   "parts": [{"path": "kenan-tepe/core.json", "bytes": …, "nodes": 3624, "relationships": 12448}, …]}]}

A bundle (.strata.json) is one site in one file, for local files and URLs:

{"format": "strata-web", "version": 1, "dataset": {…as in datasets.json}, "parts": [core, finds]}

Make one from any excavation Strata can import:

uv run strata convert my.hmcx -o my-dig.strata.json                       # a Harris matrix, in one step
uv run strata --db my-dig.rl export-web --site my-dig --bundle my-dig.strata.json   # a site already in a store

The viewer rebuilds the graph with UNWIND $rows AS r CREATE (n:Label {…}) in batches of 1,000. Labels, keys and property names must be plain identifiers; values are passed as parameters, and only http(s) links become clickable.

Python API

from strata.store import Store
from strata import queries as Q, edits as E

with Store("data/strata.rl", read_only=True) as s:
    Q.describe(s, "Area F/Trench 1/Locus 1032")
    Q.relation(s, "Area F/Trench 7/Locus 7042", "Area F/Trench 7/Locus 7044")
    s.run("MATCH (i:Issue) RETURN i.kind AS kind, count(*) AS n")       # autocommit
    s.read("MATCH (c:Context) RETURN c.path LIMIT 5")                   # always rolled back

with Store("my-copy.rl") as s:
    try:
        E.propose_relation(s, "Area D/Trench 6/Locus 53", "Area D/Trench 6/Locus 20", note="…")
    except E.Rejected as r:
        print(r.reason, r.evidence["chain"])

.github/workflows/pages.yml publishes web/; desktop.yml builds strata.mcpb on version tags.

Cache safety. Scripts and styles are referenced with ?v=dev, which the Pages workflow replaces with the commit hash, so a browser never mixes two deploys. Data parts are versioned by their build time. New imports in web/ must keep the suffix.

Limits and known issues

  • The browser loads a copy. Relate's WASM build runs in memory and cannot open .rl files, so the viewer loads a JSON export, which takes a few seconds. Changes made in the page are not saved.
  • Rebuilds start from the published record. strata build recreates data/strata.rl from the sources; edits in it are lost. Work in a copy (the desktop extension does).
  • Relate 1.2 query shapes. Strata avoids a few patterns that are slow or unsupported in this version: shortestPath with a filter on its relationships hangs when no path exists (hence :CONTESTED as its own type); shortestPath with a minimum length; nested pattern comprehensions; and, in the WASM build, COUNT { … } over a variable-length path.
  • Dates are field phasing. Kenan Tepe's periods are tentative. A period inversion is a question for a specialist, not an error in itself.
  • WebMCP is new. The API is a draft and changes between browser versions. The viewer supports both current spellings.
  • Asking a model costs money and answers vary by model. Small models may call tools badly or stop early; the panel gives up after 14 rounds of tool use. Answers are a model's reading of the record, not part of it.
